## Codebase Patterns
- serde (v1, with "derive" feature) and serde_json (v1) are dependencies of engram-core for serialization
- serde_json v1 is also a direct dependency of engram-ingest (for package.json parsing in commands.rs)
- Use `#[serde(rename_all = "snake_case")]` on enums for consistent JSON field naming
- Rust workspace uses `resolver = "2"` in root Cargo.toml
- Library crates have `src/lib.rs`, only engram-cli has `src/main.rs`
- Each crate has a `project.json` for Nx orchestration wrapping Cargo commands
- Use `cargo clippy --workspace -- -D warnings` for typecheck/lint verification
- async-trait v0.1 is used for async trait definitions; tokio (dev-dependency) with "macros" + "rt" features for async tests
- All crate versions start at 0.1.0, edition 2021
- prd.json is at `tasks/prd.json` (not in the ralph script directory)
- Use `&Path` (not `&PathBuf`) in trait method parameters — clippy `ptr_arg` lint enforces this
- engram-core follows one-module-per-concept pattern: error.rs, chunk.rs, embedding.rs, symbol.rs, config.rs
- serde_yaml v0.9 is used for YAML config deserialization; uuid v1 (with "v4" + "serde" features) for store IDs
- Use `#[serde(default)]` on struct fields so partial YAML configs deserialize with sensible defaults
- engram-core modules are private (`mod`) with `pub use` re-exports — external crates import via `engram_core::Type`, not `engram_core::module::Type`
- Provider crates live under `crates/engram-providers/<name>/` with package name `engram-provider-<name>`
- reqwest v0.12 with "json" feature for HTTP clients; wiremock v0.6 for HTTP mock testing
- tokio dev-dependency needs "rt-multi-thread" feature for wiremock tests (not just "rt")
- git2 v0.19 for git operations; scope borrows on Repository before moving it into structs
- tempfile v3 for test isolation with temporary directories
